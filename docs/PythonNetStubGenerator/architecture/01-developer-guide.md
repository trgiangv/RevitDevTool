# PythonNetStubGenerator - Developer Guide

This guide explains how PythonNetStubGenerator works as part of RevitDevTool's Python integration.

---

## 🎯 Overview

PythonNetStubGenerator is a **class library** that generates Python type stub files (`.pyi`) from .NET assemblies. It's integrated into RevitDevTool to provide IntelliSense for Revit API when using CPython + Python.NET.

**Key Concepts:**
- Uses .NET Reflection to analyze assemblies
- Extracts XML documentation comments
- Maps .NET types to Python type hints
- Generates PEP 484-compliant stub files
- Part of RevitDevTool's build pipeline

**Integration Point:**  
When RevitDevTool initializes Python environment, it uses this library to generate stubs for `RevitAPI.dll`, `RevitAPIUI.dll`, and other Revit assemblies.

## 🏗️ How It Works

### Stub Generation Pipeline

```
┌─────────────────────────────────────────────────────────────┐
│ 1. ASSEMBLY LOADING                                         │
│    Assembly.LoadFrom(dllPath) → Type[] types               │
└────────────────┬────────────────────────────────────────────┘
                 │
┌────────────────▼────────────────────────────────────────────┐
│ 2. XML DOCUMENTATION PARSING                                │
│    XmlDocReader.Load(xmlPath) → DocComment dictionary      │
└────────────────┬────────────────────────────────────────────┘
                 │
┌────────────────▼────────────────────────────────────────────┐
│ 3. TYPE ANALYSIS                                            │
│    - Reflect on classes, methods, properties, events        │
│    - Extract signatures, parameters, return types           │
│    - Resolve generic type parameters                        │
└────────────────┬────────────────────────────────────────────┘
                 │
┌────────────────▼────────────────────────────────────────────┐
│ 4. TYPE MAPPING (.NET → Python)                             │
│    - string → str                                           │
│    - IEnumerable<T> → Iterable[T]                           │
│    - void → None                                            │
│    - Generic constraints → TypeVar                          │
└────────────────┬────────────────────────────────────────────┘
                 │
┌────────────────▼────────────────────────────────────────────┐
│ 5. STUB FILE GENERATION                                     │
│    StubWriter.WriteClass() → __init__.pyi files             │
│    - Namespace folders (e.g., Autodesk/Revit/DB/)           │
│    - Class definitions with type hints                      │
│    - Method signatures with docstrings                      │
└─────────────────────────────────────────────────────────────┘
```

## 🔧 Core Components

### 1. AssemblyAnalyzer

**Purpose:** Load and inspect .NET assemblies using Reflection

**Key Methods:**
```csharp
public class AssemblyAnalyzer
{
    public Assembly LoadAssembly(string dllPath)
    {
        return Assembly.LoadFrom(dllPath);
    }
    
    public Type[] GetExportedTypes(Assembly assembly)
    {
        return assembly.GetExportedTypes()
            .Where(t => t.IsPublic)
            .ToArray();
    }
}
```

**Design Notes:**
- Uses `Assembly.LoadFrom()` to load external DLLs
- Filters to public types only (internal types not exposed in stubs)
- Handles assembly dependency resolution

### 2. XmlDocReader

**Purpose:** Parse XML documentation files generated by C# compiler

**XML Format:**
```xml
<doc>
  <assembly><name>RevitAPI</name></assembly>
  <members>
    <member name="T:Autodesk.Revit.DB.Wall">
      <summary>Represents a wall element.</summary>
    </member>
    <member name="M:Autodesk.Revit.DB.Wall.SetLocationCurve(Autodesk.Revit.DB.Curve)">
      <summary>Sets wall location curve.</summary>
      <param name="curve">The new location curve.</param>
    </member>
  </members>
</doc>
```

**Key Methods:**
```csharp
public class XmlDocReader
{
    private XmlDocument _xmlDoc;
    
    public void LoadXml(string xmlPath)
    {
        _xmlDoc = new XmlDocument();
        _xmlDoc.Load(xmlPath);
    }
    
    public string GetSummary(string memberId)
    {
        var node = _xmlDoc.SelectSingleNode($"//member[@name='{memberId}']");
        return node?.SelectSingleNode("summary")?.InnerText.Trim() ?? "";
    }
}
```

**Member ID Format:**
- `T:Namespace.ClassName` - Type
- `M:Namespace.Class.Method(ParamType)` - Method
- `P:Namespace.Class.Property` - Property
- `E:Namespace.Class.Event` - Event

### 3. PythonTypeMapper

**Purpose:** Map .NET types to Python type hints

**Type Mapping Table:**

| .NET Type | Python Type | Import Required |
|-----------|-------------|-----------------|
| `string` | `str` | No |
| `int`, `Int32` | `int` | No |
| `double`, `Double` | `float` | No |
| `bool` | `bool` | No |
| `void` | `None` | No |
| `IEnumerable<T>` | `Iterable[T]` | `from typing import Iterable` |
| `IList<T>` | `List[T]` | `from typing import List` |
| `IDictionary<K,V>` | `Dict[K, V]` | `from typing import Dict` |
| `Nullable<T>` | `Optional[T]` | `from typing import Optional` |

**Key Methods:**
```csharp
public class PythonTypeMapper
{
    public string MapType(Type type)
    {
        // Primitive types
        if (type == typeof(string)) return "str";
        if (type == typeof(int)) return "int";
        if (type == typeof(double)) return "float";
        if (type == typeof(bool)) return "bool";
        if (type == typeof(void)) return "None";
        
        // Generic types
        if (type.IsGenericType)
        {
            return MapGenericType(type);
        }
        
        // Default: use type name
        return type.Name;
    }
    
    private string MapGenericType(Type type)
    {
        var genericDef = type.GetGenericTypeDefinition();
        var args = type.GetGenericArguments();
        
        if (genericDef == typeof(IEnumerable<>))
        {
            return $"Iterable[{MapType(args[0])}]";
        }
        
        if (genericDef == typeof(Nullable<>))
        {
            return $"Optional[{MapType(args[0])}]";
        }
        
        // Fallback for other generics
        return $"{genericDef.Name}[{string.Join(", ", args.Select(MapType))}]";
    }
}
```

### 4. StubWriter

**Purpose:** Generate Python stub file syntax

**Key Methods:**
```csharp
public class StubWriter
{
    private StringBuilder _content = new();
    private int _indentLevel = 0;
    
    public void WriteClass(Type type, string docstring)
    {
        WriteLine($"class {type.Name}:");
        Indent();
        WriteLine($'"""{docstring}"""');
        Dedent();
    }
    
    public void WriteMethod(MethodInfo method, DocComment doc)
    {
        var parameters = string.Join(", ", method.GetParameters()
            .Select(p => $"{p.Name}: {MapType(p.ParameterType)}"));
        var returnType = MapType(method.ReturnType);
        
        WriteLine($"def {method.Name}({parameters}) -> {returnType}:");
        Indent();
        WriteLine($'"""{doc.Summary}"""');
        WriteLine("...");
        Dedent();
    }
    
    public void SaveToFile(string path)
    {
        File.WriteAllText(path, _content.ToString());
    }
}
```

### 5. SymbolScope

**Purpose:** Track import dependencies for each stub file

**Why Needed:**  
Python stubs need `from typing import List, Optional, ...` at the top based on what types are used in the file.

**Key Methods:**
```csharp
public class SymbolScope
{
    private HashSet<string> _typingImports = new();
    private HashSet<string> _moduleImports = new();
    
    public void RequireTypingImport(string symbol)
    {
        // e.g., "List", "Optional", "Tuple"
        _typingImports.Add(symbol);
    }
    
    public void RequireModuleImport(string module, string symbol)
    {
        // e.g., "from Autodesk.Revit.DB import Wall"
        _moduleImports.Add($"from {module} import {symbol}");
    }
    
    public string GenerateImports()
    {
        var sb = new StringBuilder();
        
        if (_typingImports.Any())
        {
            sb.AppendLine($"from typing import {string.Join(", ", _typingImports)}");
        }
        
        foreach (var import in _moduleImports)
        {
            sb.AppendLine(import);
        }
        
        return sb.ToString();
    }
}
```

## 🎨 Extension Points

### Adding New Type Mappings

**Scenario:** Map `System.Tuple<T1, T2>` to Python `tuple[T1, T2]`

**Implementation in PythonTypeMapper.cs:**

```csharp
public string MapType(Type type)
{
    // Existing mappings...
    
    // Add Tuple mapping
    if (type.IsGenericType && type.GetGenericTypeDefinition() == typeof(Tuple<,>))
    {
        var typeArgs = type.GetGenericArguments();
        var mappedArgs = string.Join(", ", typeArgs.Select(MapType));
        return $"tuple[{mappedArgs}]";
    }
    
    return type.Name;
}
```

**Result:**
```python
def GetNameAndAge(self) -> tuple[str, int]: ...
```

### Handling Generic Constraints

**Scenario:** .NET generic constraints like `where T : struct`

**Challenge:** Python TypeVars don't directly support value type constraints

**Current Approach:** Document in docstring

```csharp
// In StubWriter.cs
if (typeParam.Attributes.HasFlag(GenericParameterAttributes.NotNullableValueTypeConstraint))
{
    docstring += "\n\n    Note: Type parameter T must be a value type.";
}
```

**Alternative Using Protocol:**

```python
from typing import Protocol, TypeVar

class ValueType(Protocol):
    """Marker protocol for value types."""
    pass

T = TypeVar('T', bound=ValueType)

def ProcessValue(value: T) -> T: ...
```

### Improving Docstring Extraction

**Current:** Basic `<summary>` tag extraction

**Enhancement:** Extract parameter docs and return types

**In `XmlDocReader.cs`:**

```csharp
public DocComment GetMethodDoc(MethodInfo method)
{
    var memberId = XmlMemberIdBuilder.GetMemberId(method);
    var xmlNode = _xmlDoc.SelectSingleNode($"//member[@name='{memberId}']");
    
    if (xmlNode == null) return DocComment.Empty;
    
    var summary = xmlNode.SelectSingleNode("summary")?.InnerText.Trim();
    var returns = xmlNode.SelectSingleNode("returns")?.InnerText.Trim();
    
    // Extract parameter docs
    var paramDocs = new Dictionary<string, string>();
    foreach (XmlNode paramNode in xmlNode.SelectNodes("param"))
    {
        var name = paramNode.Attributes["name"]?.Value;
        var desc = paramNode.InnerText.Trim();
        if (name != null) paramDocs[name] = desc;
    }
    
    return new DocComment(summary, paramDocs, returns);
}
```

**In `StubWriter.cs`:**

```csharp
public void WriteMethod(MethodInfo method, DocComment doc)
{
    WriteLine($"def {method.Name}(");
    
    // Add parameters with inline docs
    foreach (var param in method.GetParameters())
    {
        var paramDoc = doc.ParamDocs.TryGetValue(param.Name, out var d) ? $"  # {d}" : "";
        WriteLine($"    {param.Name}: {MapType(param.ParameterType)},{paramDoc}");
    }
    
    WriteLine($") -> {MapType(method.ReturnType)}:");
    
    // Add docstring with return doc
    if (!string.IsNullOrEmpty(doc.Summary))
    {
        WriteLine($'    """{doc.Summary}');
        if (!string.IsNullOrEmpty(doc.Returns))
        {
            WriteLine($"    ");
            WriteLine($"    Returns:");
            WriteLine($"        {doc.Returns}");
        }
        WriteLine($'    """');
    }
    
    WriteLine("    ...");
}
```

**Result:**
```python
def Calculate(
    value: int,  # The input value to process
    options: str,  # Processing options (comma-separated)
) -> float:
    """Calculates a result based on input.
    
    Returns:
        The computed result value.
    """
    ...
```

### Handling Overloaded Methods

**Current:** May generate duplicate signatures or collapse to `Any`

**Better approach:** Use `@overload` decorator

**In `StubWriter.cs`:**

```csharp
public void WriteOverloadedMethods(MethodInfo[] overloads)
{
    if (overloads.Length == 1)
    {
        WriteMethod(overloads[0]);
        return;
    }
    
    // Multiple overloads: use @overload
    foreach (var method in overloads)
    {
        WriteLine("@overload");
        WriteMethod(method);
    }
    
    // Add final implementation signature (required by mypy)
    WriteLine($"def {overloads[0].Name}(*args, **kwargs) -> Any: ...");
}
```

**Result:**
```python
from typing import overload, Any

@overload
def SetValue(self, value: int) -> None: ...

@overload
def SetValue(self, value: str) -> None: ...

def SetValue(*args, **kwargs) -> Any: ...  # Implementation signature
```

## 🔍 Integration with RevitDevTool

### When Stubs Are Generated

**Trigger Points:**
1. **First-time Python initialization** - Generate stubs for Revit API assemblies
2. **Revit version change** - Regenerate when switching Revit versions
3. **Manual regeneration** - User requests stub refresh via settings

**Integration Code (in RevitDevTool):**

```csharp
public class PythonEnvironmentInitializer
{
    private readonly IStubGeneratorService _stubGenerator;
    
    public void InitializePythonEnvironment(string revitVersion)
    {
        var revitApiPath = GetRevitApiPath(revitVersion);
        var stubsPath = GetStubsPath();
        
        if (!StubsExist(stubsPath) || StubsOutdated(stubsPath, revitApiPath))
        {
            _stubGenerator.GenerateStubs(
                targetDlls: new[] { 
                    $"{revitApiPath}/RevitAPI.dll",
                    $"{revitApiPath}/RevitAPIUI.dll"
                },
                outputPath: stubsPath
            );
        }
        
        // Configure Python to use generated stubs
        ConfigurePythonPath(stubsPath);
    }
}
```

### Stub File Organization

**Output Structure:**
```
stubs/
├── Autodesk/
│   └── Revit/
│       ├── DB/
│       │   └── __init__.pyi       # Core database types (Wall, Element, etc.)
│       ├── UI/
│       │   └── __init__.pyi       # UI types (UIApplication, etc.)
│       └── ApplicationServices/
│           └── __init__.pyi       # Application services
└── System/
    └── __init__.pyi               # .NET framework types used by Revit API
```

**Why This Structure:**
- Matches .NET namespace hierarchy
- Allows `from Autodesk.Revit.DB import Wall` in Python
- Each namespace gets its own `__init__.pyi` file

### Performance Considerations

**Assembly Loading:**
- Revit API assemblies are 10-50 MB each
- Loading time: 100-500ms per assembly
- Optimization: Lazy load only required assemblies

**Stub Generation:**
- ~5000 types in RevitAPI.dll
- Generation time: 2-5 seconds
- Optimization: Cache generated stubs, regenerate only on version change

**File I/O:**
- Write thousands of stub files
- Optimization: Buffer writes, use parallel I/O for different namespaces

## 🚀 Performance Optimization

### Parallel Processing

**Optimization:** Parallelize type analysis (file I/O must remain sequential)

```csharp
using System.Threading.Tasks;
using System.Collections.Concurrent;

public void GenerateStubs(Assembly assembly)
{
    var types = assembly.GetExportedTypes();
    var stubs = new ConcurrentBag<StubDefinition>();
    
    // Parallel type analysis
    Parallel.ForEach(types, type =>
    {
        var stub = GenerateStubForType(type);
        stubs.Add(stub);
    });
    
    // Sequential file writing
    foreach (var stub in stubs)
    {
        writer.WriteStub(stub);
    }
}
```

**Expected Speedup:** 2-4x on multi-core systems for large assemblies

### XML Doc Caching

**Optimization:** Pre-parse XML documentation into dictionary

```csharp
private Dictionary<string, XmlNode> _docCache;

public void LoadXmlDocs(string xmlPath)
{
    var doc = new XmlDocument();
    doc.Load(xmlPath);
    
    _docCache = new Dictionary<string, XmlNode>();
    foreach (XmlNode node in doc.SelectNodes("//member"))
    {
        var name = node.Attributes["name"]?.Value;
        if (name != null) _docCache[name] = node;
    }
}

public DocComment GetDoc(string memberId)
{
    return _docCache.TryGetValue(memberId, out var node)
        ? ParseDocComment(node)
        : DocComment.Empty;
}
```

**Expected Speedup:** 10x faster doc lookups for large XML files

## 🐛 Common Issues

### Missing Imports

**Symptom:**
```python
class MyClass:
    def GetList(self) -> List[str]: ...  # NameError: List not defined
```

**Cause:** `SymbolScope` not tracking `List` usage

**Fix:** Ensure type mapper calls `scope.RequireTypingImport("List")` when mapping `IList<T>`

### Circular Dependencies

**Symptom:**
```python
from ModuleA import ClassA

class ClassB:
    def GetA(self) -> ClassA: ...  # ClassA not yet defined
```

**Cause:** Forward reference needed

**Fix:** Use string literals for forward references:
```python
def GetA(self) -> "ClassA": ...
```

### Generic Arity in Type Names

**Symptom:**
```python
def GetItems(self) -> IEnumerable`1[Wall]: ...  # Backticks in name
```

**Cause:** .NET uses backticks for generic arity (`List`1`, `Dictionary`2`)

**Fix:** Strip arity suffix in type mapper:
```csharp
if (type.Name.Contains("`"))
{
    var baseName = type.Name.Substring(0, type.Name.IndexOf('`'));
    var args = type.GetGenericArguments();
    return $"{baseName}[{string.Join(", ", args.Select(MapType))}]";
}
```
