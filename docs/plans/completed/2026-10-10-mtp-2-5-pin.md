# Execution Plan: MTP 2.5 / MSTest 4.5 / TUnit 1.73 Pin

Date: 2026-10-10

## Status

Completed

## Outcome

RevitDevTool and standalone in-repo tests run on Microsoft.Testing.Platform
2.5.1, MSTest 4.5.1, and TUnit 1.73.19. The in-host MSTest session cancels
through `TestApplicationOptions.CancellationToken`. `MSTestPlatformPolicy.Cancel`
is gone.

## Context

[0042](../../decisions/0042-mtp-2-5-removable-test-workarounds.md). Current
pins are MSTest 4.4.1, MTP 2.4.1, TUnit 1.72.10
([0035](../../decisions/0035-mstest-sdk-repo-tests.md),
[0038](../../decisions/0038-mstest-host-provider.md)).

## Scope

In scope:

- Central and project pins, generation version checks, payload identity check.
- Public cancel token on `MSTestRuntimeSession`.
- Focused host/runtime/adapter tests and the consumer-facing pin text those
  tests and authors copy.

Out of scope:

- `MSTest.Extensions.Hosting`, assertion-failure diagnostics, OpenTelemetry.
- Moving TUnit in-host onto `TestApplication` / `AddTUnit`.
- Deleting discovery reflection, console capture, `[DependsOn]` closure,
  `TUnitSourceCatalog`, or `TUnitEngineBindings`.
- Live Revit two-generation proof (still open on the MSTest provider plan).
- Packing or publishing `RevitDevTool.TestAdapter`.

## Approach

1. Bump `Directory.Packages.props`, `global.json`, MSTest package versions,
   `MSTestGenerationPolicy`, `TUnitGenerationPolicy`, and the runtime payload
   identity check together.
2. Pass the run token into `TestApplication.CreateBuilderAsync` and delete
   the internal cancel reflection.
3. Update tests that assert the old assembly versions and the consumer
   package references.
4. Update product, architecture cancel row, adapter README, and the
   revit-test skill so a new project copies 4.5.1 / 2.5.1 / 1.73.19.
5. Amend 0035 and 0038 with a pointer. Mark 0042 Accepted only after the
   focused tests pass.

## Risks And Recovery

- TUnit 1.73 can break `TUnitEngineBindings` if the engine constructor
  changes. Recovery: the binding resolve test fails by member name; revert
  the TUnit pin only if that member is gone.
- MSTest or MTP assembly version may not equal the package version.
  Recovery: read the built DLL identity and set the generation pin to that
  version.
- NUnit testhost compiles against the same central MTP. Recovery: fix the
  NUnit.MTP compile error or keep NUnit on the previous MTP only if the
  API break is real. Do not leave two MTP versions in one testhost.
