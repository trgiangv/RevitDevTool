#### `object?` evidence (2026-09-04)

`InvokeCapabilityResponse.Result` and `ResourceReadResult.Result` remain `object?`.

**Single `invoke_dynamic`:** `ToHostCallToolResult` unwraps `CallToolResult` /
`ReadResourceResult` into native MCP content. Happy-path `object?` never hits
JSON. Errors serialize `DynamicInvocationError` only.

**Batch `reads[]`:** production serializes the envelope with
`McpToolJson.Options` (source-gen **plus** SDK protocol chain). SDK converters
handle nested `ReadResourceResult`. Harness
`InvokeDynamic_BatchReadsFixedAndTemplateResources` **passes** (2 ok items).

**Bare source-gen** (`McpServerJsonContext.Default.InvokeCapabilityResponse`)
**throws** `NotSupportedException` when `Result` holds SDK
`ReadResourceResult` — `InvokeCapabilityResponseSerializationTests` **passes by
asserting that throw**. That path is not the production write.

**Still needed before [0032](../../decisions/0032-daemon-mewui-and-aot.md) AOT:**
close `object?` so the envelope serializes without reflection / Options fallback.
May change batch result JSON shape/counts. Capture goldens first. Do not treat
the characterization throw as a JIT failure.
